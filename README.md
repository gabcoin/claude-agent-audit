# Claude Code Agent Audit

A portable local analyzer for **Claude Code session history**.

It scans the `.jsonl` files generated by Claude Code and helps you
understand:

-   which tools Claude uses most;
-   which subagents are actually being invoked;
-   which sessions are agent-heavy;
-   how much token/cache activity appears in each session;
-   what prompts are being sent to agents;
-   what agents return;
-   what the parent Claude session does immediately afterward.

The goal is simple: **understand where your Claude Code usage is going
and whether your subagents are providing enough value to justify their
cost.**

> This tool is read-only. It does not modify Claude Code sessions,
> agents, settings, or project files.

## Why?

Long Claude Code sessions can accumulate very large contexts. Subagents
can add another layer of cost because each agent may perform its own
reads, searches, reasoning, and tool calls.

Claude Code Agent Audit turns local session history into a report you
can inspect instead of guessing.

It can help answer questions such as:

-   Am I overusing `Explore` or `general-purpose` agents?
-   Which sessions spawn the most agents?
-   Are agents being used for simple tasks the parent could handle?
-   Which sessions have extremely high cache reads?
-   What did an agent actually receive as its prompt?
-   Did the parent repeat the same investigation after the agent
    returned?
-   Which tools dominate my Claude Code workflow?

## Requirements

-   Python 3.9+ recommended
-   Claude Code
-   Existing local Claude Code session history

No third-party Python packages are required.

## Supported platforms

-   Windows
-   macOS
-   Linux

By default, the script looks for Claude Code data in:

``` text
~/.claude/projects/
```

If `CLAUDE_CONFIG_DIR` is defined, the script respects it automatically.

You can also specify a custom Claude directory with `--claude-dir`.

## Installation

Clone the repository:

``` bash
git clone <YOUR-REPOSITORY-URL>
cd claude-code-agent-audit
```

Or download `claude-agent-audit.py` directly.

No `pip install` step is required.

## Quick start

### Windows

``` powershell
py .\claude-agent-audit.py --output agent-audit.txt
```

### macOS / Linux

``` bash
python3 claude-agent-audit.py --output agent-audit.txt
```

The report is written as UTF-8, including on Windows.

## Usage

### Analyze all Claude Code history

``` bash
python3 claude-agent-audit.py --output agent-audit.txt
```

Windows:

``` powershell
py .\claude-agent-audit.py --output agent-audit.txt
```

### Analyze one project

The filter matches text in the session path:

``` bash
python3 claude-agent-audit.py \
  --project numerologia \
  --output numerologia-audit.txt
```

### Analyze one session

Use the session UUID or another unique part of its path:

``` bash
python3 claude-agent-audit.py \
  --session ff29b6fc-beae-40e5-8e58-bdec0236c374 \
  --output session-audit.txt
```

### Generate TXT and JSON

``` bash
python3 claude-agent-audit.py \
  --output agent-audit.txt \
  --json agent-audit.json
```

The JSON output is useful if you want to analyze the results
programmatically.

### Generate only the summary

Detailed agent prompts/results can make reports large.

Use:

``` bash
python3 claude-agent-audit.py \
  --no-details \
  --output summary.txt
```

### Show more top results

``` bash
python3 claude-agent-audit.py \
  --top 50 \
  --output agent-audit.txt
```

### Use a custom Claude directory

``` bash
python3 claude-agent-audit.py \
  --claude-dir /path/to/.claude \
  --output agent-audit.txt
```

## Command-line options

  -----------------------------------------------------------------------
  Option                              Description
  ----------------------------------- -----------------------------------
  `--project TEXT`                    Analyze only paths containing the
                                      specified project text

  `--session TEXT`                    Analyze only a matching
                                      session/path

  `--output FILE`                     Write the human-readable report to
                                      a UTF-8 text file

  `--json FILE`                       Write a machine-readable JSON
                                      report

  `--top N`                           Number of top entries to display;
                                      default is 30

  `--no-details`                      Skip detailed agent prompt/result
                                      sections

  `--claude-dir PATH`                 Override the Claude configuration
                                      directory
  -----------------------------------------------------------------------

Run:

``` bash
python3 claude-agent-audit.py --help
```

for the current CLI reference.

## What the report contains

### Global tool use

Counts tool calls across the scanned histories.

Example:

``` text
=== GLOBAL TOOL USE ===
   2521  Bash
   1371  Read
   1157  Edit
    435  Write
    308  Grep
     89  WebSearch
     77  Agent
```

This gives you a high-level view of how Claude is working.

### Agent usage

The report identifies explicit agent/delegation calls and attempts to
extract the agent type.

Example:

``` text
=== AGENTS ===
     15  Explore
      8  general-purpose
      5  UI Designer
      4  UX Architect
      3  Product Manager
      2  Software Architect
```

This is useful when you have a large agent library but don't know which
agents Claude actually uses.

### Agent-heavy sessions

Sessions are ranked by the number of detected agent calls.

Example:

``` text
=== MOST AGENT-HEAVY SESSIONS ===

.../6155ccef-17b3-4f9c-ac72-6c7ef6e38b9f.jsonl
  Agents:         14
  Tools:          585
  Output:         2,884,534
  Cache read:     603,980,393
  Cache creation: 66,693,738
```

A high number here does **not automatically mean the agents were
wasteful**. It identifies sessions worth investigating.

### Heavy sessions by cache reads

The tool also ranks parent sessions by recorded cache-read tokens.

This can expose an important pattern: a session may be extremely
expensive or context-heavy **even when it barely uses agents**.

In other words, agent usage and long-session context growth should be
analyzed separately.

### Individual agent calls

Unless `--no-details` is enabled, the report includes individual agent
calls with:

-   parent session;
-   project;
-   JSONL line;
-   agent name/type;
-   description;
-   tool-use ID;
-   prompt sent to the agent;
-   matched agent result when available;
-   nearby parent activity after the agent call.

This makes qualitative analysis possible.

For example, you can investigate whether this happened:

``` text
Parent Claude
    |
    +-- Explore agent
    |      reads/searches codebase
    |      returns relevant files
    |
    +-- Parent immediately repeats same exploration
```

That may indicate low-value delegation.

Compare it with:

``` text
Parent Claude
    |
    +-- Security specialist
           finds concrete vulnerability

Parent uses finding and fixes vulnerability
```

That may justify the extra agent context.

## How to evaluate agent ROI

Invocation count alone is not enough.

A useful review framework is:

### High value

The agent:

-   discovers information the parent did not already have;
-   finds a real bug or risk;
-   provides specialist expertise;
-   handles meaningful parallel work;
-   produces a result the parent directly uses;
-   substantially reduces parent exploration.

### Medium value

The agent:

-   provides useful perspective;
-   contributes to the solution;
-   duplicates some parent work;
-   helps, but probably wasn't essential.

### Low value

The agent:

-   performs simple file discovery;
-   repeats work the parent could do with a few `Read`, `Grep`, or
    `Glob` calls;
-   returns obvious information;
-   causes the parent to repeat most of the investigation.

### Likely waste

The agent:

-   produces output that is ignored;
-   duplicates another agent;
-   investigates the wrong area;
-   is spawned as part of unnecessary orchestration;
-   adds another large context without affecting the final solution.

## Understanding the token numbers

The audit reports token fields recorded in Claude Code's local JSONL
history, including:

-   input tokens;
-   output tokens;
-   cache-read input tokens;
-   cache-creation input tokens.

These numbers are useful for comparing sessions and identifying
patterns.

They should **not be treated as a billing statement**.

Prompt caching can be working correctly while a workflow is still
expensive. A very long session can repeatedly operate against a huge
cached context.

For example:

``` text
small session
    -> moderate context

long session
    -> large context
    -> more tool output
    -> more conversation history
    -> repeated large cache reads
```

So optimizing Claude Code usage often involves both:

1.  controlling unnecessary agent delegation;
2.  controlling parent-session/context growth.

## Privacy

All analysis is performed locally.

The script reads Claude Code history from your machine and does not
upload it anywhere.

However, **generated reports may contain sensitive information** because
detailed mode can include:

-   prompts;
-   commands;
-   file paths;
-   tool results;
-   project information.

Review reports before sharing or committing them.

It is a good idea to add audit outputs to `.gitignore`:

``` gitignore
agent-audit*.txt
agent-audit*.json
*-audit.txt
```

Never publish reports containing secrets, credentials, private source
code, personal information, or confidential project data.

## Read-only behavior

The analyzer only reads Claude Code history files.

It does not:

-   edit `.jsonl` histories;
-   change Claude settings;
-   modify agents;
-   modify `CLAUDE.md`;
-   delete sessions;
-   invoke Claude;
-   send prompts to an API.

## Limitations

Claude Code's local session format can evolve over time.

Because of that:

-   some agent results may not be directly matched;
-   third-party plugins may invoke agents through mechanisms the
    detector does not recognize;
-   agent names depend on the information stored in the tool call;
-   JSONL file size is not equivalent to model token usage;
-   token fields in local history should be interpreted as diagnostic
    data, not exact billing data;
-   qualitative agent value still requires reviewing what the agent
    actually accomplished.

The script intentionally avoids claiming that an agent is wasteful
solely because it used many tokens.

## Suggested workflow

A practical optimization workflow:

``` text
1. Run full audit
        |
2. Find agent-heavy sessions
        |
3. Find highest cache-read sessions
        |
4. Inspect most-used agents
        |
5. Review representative agent calls
        |
6. Identify duplicated work
        |
7. Restrict generic agents
        |
8. Keep valuable specialists
        |
9. Re-run audit after workflow changes
```

For long-running projects, also consider persisting durable knowledge
into project documentation or `CLAUDE.md` rather than keeping one
conversation alive indefinitely.

## Example optimization rules

After auditing your own usage, you may decide to add rules such as:

``` markdown
Do not spawn subagents by default.

Use a subagent only when:
- work can be meaningfully parallelized;
- specialist expertise is materially useful;
- an independent review provides clear value.

Do not use generic exploration agents for tasks the main agent can
complete with a few Read/Grep/Glob calls.

Avoid multi-agent orchestration for small changes.
```

These are examples only. The purpose of the audit is to help you create
rules based on **your actual usage**.
